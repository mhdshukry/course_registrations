# RUSL production database

The authoritative schema is `production_schema.sql`. It installs into
`rusl_course_registration_v2` and intentionally leaves the older prototype
database untouched. `production_seed.sql` supplies development data for the
five supported roles.

## Organization and access scope

```text
University / Super Admin
└── Faculty
    ├── Dean (faculty-wide academic oversight)
    ├── Assistant Registrar (faculty-wide registry administration)
    └── Department
        ├── Head of Department (department-wide authority)
        └── Students (own records only)
```

Dean and Assistant Registrar assignments carry `faculty_id` and no
`department_id`. HoD assignments carry both. Student records carry faculty,
department, programme, and curriculum foreign keys. Super Admin has a null
scope and university-wide authority.

## Installation

```powershell
mysql -u root --execute="source database/production_schema.sql"
mysql -u root --execute="source database/production_seed.sql"
```

Use a restricted application account in deployed environments; the Laravel
API must never connect as `root`.

## Authoritative workflow

`DRAFT -> SUBMITTED -> HOD_APPROVED -> AR_APPROVED -> LOCKED`

The transition procedures reject skipped stages and unauthorized roles.
Super Admin can exercise staff authority but all actions remain auditable.

## CRUD/API contract

| Resource | Create | Read | Update | Delete / lifecycle |
|---|---|---|---|---|
| Faculties | `POST /faculties` | `GET /faculties[/{id}]` | `PUT /faculties/{id}` | `DELETE /faculties/{id}` (deactivate) |
| Departments | `POST /departments` | `GET /departments[/{id}]` | `PUT /departments/{id}` | `DELETE /departments/{id}` (deactivate) |
| Programmes | `POST /programmes` | `GET /programmes[/{id}]` | `PUT /programmes/{id}` | `DELETE /programmes/{id}` (deactivate) |
| Curricula | `POST /curricula` | `GET /curricula[/{id}]` | `PUT /curricula/{id}` | `DELETE /curricula/{id}` (supersede) |
| Courses | `POST /courses` | `GET /courses[/{id}]` | `PUT /courses/{id}` | `DELETE /courses/{id}` (deactivate) |
| Offerings | `POST /offerings` | `GET /offerings[/{id}]` | `PUT /offerings/{id}` | `DELETE /offerings/{id}` (cancel) |
| Timetable | `POST /timetable-slots` | `GET /timetable-slots` | `PUT /timetable-slots/{id}` | `DELETE /timetable-slots/{id}` |
| Users/staff | `POST /users` | `GET /users[/{id}]` | `PUT /users/{id}` | `DELETE /users/{id}` (disable) |
| Students | `sp_create_student` | `GET /students[/{id}]` | `sp_update_student` | `sp_delete_student` (soft delete) |
| Registrations | create draft automatically | `GET /registrations[/{id}]` | `sp_save_registration_course`, `sp_drop_registration_course` | locked records cannot be deleted |
| HoD decision | — | `v_hod_registration_queue` | `sp_hod_decide_registration` | — |
| AR decision | — | `v_ar_registration_queue` | `sp_ar_decide_registration`, `sp_final_lock_registration` | — |
| Academic results | `sp_upsert_academic_result` | `v_student_academic_progress` | `sp_upsert_academic_result` | `sp_delete_academic_result` (Super Admin only) |
| Special requests | `POST /special-requests` | `GET /special-requests` | `POST /special-requests/{id}/review` | student cancellation before review |
| Notifications | generated by workflow | `GET /notifications` | `PATCH /notifications/{id}/read` | retention-policy only |
| Audit logs | generated only | `GET /audit-logs` | prohibited | prohibited |

## Views

- `v_student_academic_progress`: degree credits split into Completed, Medical,
  and Dropped. Only Completed credits contribute to degree completion.
- `v_registration_workflow`: full cross-portal workflow projection.
- `v_hod_registration_queue`: registrations currently requiring HoD action.
- `v_ar_registration_queue`: registrations currently requiring AR action.
- `v_student_timetable`: student timetable derived from selected offerings.

## Functions and procedures

- `fn_completed_credits`
- `fn_registration_total_credits`
- `fn_user_has_role`
- `fn_degree_credit_requirement_met`
- `sp_create_student`, `sp_update_student`, `sp_delete_student`
- `sp_save_registration_course`, `sp_drop_registration_course`
- `sp_submit_registration`
- `sp_hod_decide_registration`
- `sp_ar_decide_registration`
- `sp_final_lock_registration`
- `sp_upsert_academic_result`, `sp_delete_academic_result`

There is deliberately no waiting-list table or workflow. Compulsory subjects
are curriculum assignments; students choose only optional subjects.
